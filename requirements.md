# SlotGrid: требования к платформе составления расписания

**SlotGrid** — веб-платформа составления расписания для университета. Работает только на компьютере, мобильной версии нет. Платформа отвечает только за то, **когда, где и с кем проходят занятия**. Оценки, материалы и задания в неё не входят.

Нумерация FR сохранена от прошлых версий. Удалённые номера (FR-010, 033, 054, 084, 092, 095, 101–103) не используются повторно. Второй очереди нет: всё, что перечислено ниже, входит в продукт.

---

## 1. Роли

| ID | Роль | Что делает |
|----|------|-----------|
| R-1 | Администратор системы | Создаёт пользователей, назначает роли, настраивает систему, следит за копиями данных |
| R-2 | Составитель расписания | Вводит данные, задаёт правила, строит и правит расписание, публикует, оформляет замены |
| R-3 | Преподаватель | Указывает, когда недоступен, видит своё расписание, отмечает отсутствие |

Студентов и руководителей в системе как пользователей нет. Студенты смотрят опубликованное расписание группы по публичной ссылке или в PDF.

---

## 2. Справочники и исходные данные

| ID | Функция |
|----|---------|
| FR-001 | Учебный период: год, семестр, даты начала и конца, каникулы. Учебная неделя фиксированная: пять дней (пн–пт) |
| FR-002 | Сетка звонков: номера пар (до 8 в день), время начала и конца |
| FR-003 | Предметы: название, код, тип занятия (лекция, практика, лаборатория) |
| FR-004 | Преподаватели: какие предметы ведут, максимум пар в день |
| FR-005 | Группы: название, размер |
| FR-006 | Аудитории: номер, корпус, вместимость, тип |
| FR-007 | Учебный план: сколько пар каких предметов нужно каждой группе в неделю и кто их ведёт |
| FR-008 | Импорт справочников из Excel и CSV с предпросмотром и списком ошибок до сохранения |
| FR-009 | Копирование данных прошлого семестра в новый |

## 3. Правила и исключения

### 3.1. Обычные правила (нельзя нарушать)

| ID | Правило |
|----|---------|
| FR-020 | Преподаватель не может вести два занятия одновременно |
| FR-021 | Группа не может быть на двух занятиях одновременно |
| FR-022 | Аудитория не может быть занята двумя занятиями одновременно |
| FR-023 | Вместимость аудитории не меньше размера группы |
| FR-024 | Тип аудитории подходит занятию (лабораторная идёт в лаборатории) |
| FR-025 | Преподаватель не ставится на время, когда он недоступен |
| FR-026 | Не больше N пар в день у группы и у преподавателя. N задаётся в настройках; у преподавателя берётся его личный максимум (FR-004), если он указан |

### 3.2. Исключения

| ID | Функция |
|----|---------|
| FR-030 | Разовое изменение: занятие меняется только на одну дату, постоянное расписание не меняется |
| FR-031 | Праздники и нерабочие дни: занятия на эти даты не планируются |
| FR-032 | Фиксация занятия: оно остаётся на месте при перегенерации |

Правило нарушить нельзя. Правку, которая его нарушает, система не применяет и объясняет причину.

## 4. Генерация и редактирование

| ID | Функция |
|----|---------|
| FR-040 | Автоматическая генерация расписания по правилам |
| FR-041 | Остановка генерации с сохранением лучшего варианта на этот момент |
| FR-042 | Ручное размещение занятий перетаскиванием |
| FR-043 | При перетаскивании подсвечиваются допустимые слоты (зелёным) и недопустимые (красным) |
| FR-044 | Поиск свободной аудитории по дню, паре, вместимости и типу |

---

## 5. Конфликты

| ID | Функция |
|----|---------|
| FR-050 | Обнаружение конфликтов при любой правке и при изменении данных |
| FR-051 | Понятная причина конфликта: какое правило нарушено, кто и что в конфликте |
| FR-052 | Предпросмотр последствий правки до применения: кого она затрагивает. Показывается для опубликованного расписания; в черновике правка применяется сразу |
| FR-053 | Если часть занятий не удалось разместить, список таких занятий с причиной по каждому |

Как возникают конфликты. Перетаскивание на недопустимый слот блокируется сразу. Уже стоящее занятие становится конфликтным, если данные изменились после построения (например, преподаватель указал недоступные часы или у аудитории уменьшили вместимость). Такое занятие помечается красным, причина показывается в панели занятия.

## 12. Нефункциональные требования

| ID | Требование |
|----|-----------|
| NFR-01 | Автогенерация расписания университета укладывается в разумное время (минуты) и может быть остановлена |
| NFR-02 | Проверка конфликтов при правке занимает доли секунды |
| NFR-03 | Доступ по ролям, пароли хранятся в защищённом виде, соединение зашифровано |
| NFR-04 | Интерфейс работает в современных браузерах на компьютере. Мобильная версия не требуется |
| NFR-05 | Простой старт: пошаговая первоначальная настройка |

---

## 13. Вне рамок

- Оценки, домашние задания, учебные материалы (задачи LMS).
- Мобильная версия.
- Роли студента, родителя, руководителя.
- Выбор курсов студентами, индивидуальные расписания.
- Экзамены и бронирование аудиторий под мероприятия.
- Мягкие ограничения с весами, несколько вариантов расписания, сценарии «что если».
- Чётные и нечётные недели.
- Осознанное нарушение правила с указанием причины.
- Проверка данных перед генерацией.
- Подсветка изменений у преподавателя.
- Подписка на расписание в календарь (iCal).
- Отчёты по группам и аудиториям.
- Интеграции со SIS и LMS, SSO, открытый API.
- Несколько кампусов и факультетов в одной системе.
- Шестидневная неделя и занятия по субботам.
- Узбекский язык интерфейса.
