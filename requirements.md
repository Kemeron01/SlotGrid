# SlotGrid: требования к платформе составления расписания (упрощённая версия для университета)

**SlotGrid** — платформа составления расписания для университета. Она отвечает только за то, **когда, где и с кем проходят занятия**. Оценки, материалы и задания в неё не входят.

**Приоритет:** `MVP` — первая версия; `V2` — вторая очередь.

---

## 1. Роли

| ID | Роль | Что делает |
|----|------|-----------|
| R-1 | Администратор системы | Создаёт пользователей, назначает роли, настраивает систему, следит за копиями данных |
| R-2 | Составитель расписания | Вводит данные, задаёт правила, строит и правит расписание, публикует, оформляет замены |
| R-3 | Преподаватель | Указывает, когда недоступен, видит своё расписание, отмечает отсутствие |

Студентов и руководителей в системе как пользователей нет. Студенты смотрят опубликованное расписание по общей ссылке, в PDF или в календаре.

## 3. Правила, исключения

### 3.1. Обычные правила (нельзя нарушать)

| ID | Правило | Приоритет |
|----|---------|-----------|
| FR-020 | Преподаватель не может вести два занятия одновременно | MVP |
| FR-021 | Группа не может быть на двух занятиях одновременно | MVP |
| FR-022 | Аудитория не может быть занята двумя занятиями одновременно | MVP |
| FR-023 | Вместимость аудитории не меньше размера группы | MVP |
| FR-024 | Тип аудитории подходит занятию (лабораторная идёт в лаборатории) | MVP |
| FR-025 | Преподаватель не ставится на время, когда он недоступен | MVP |
| FR-026 | Не больше N пар в день у группы и у преподавателя (N задаётся в настройках) | MVP |

### 3.2. Исключения

| ID | Функция | Приоритет |
|----|---------|-----------|
| FR-030 | Разовое исключение: изменение занятия только на одну дату, постоянное расписание не меняется | MVP |
| FR-031 | Праздники и нерабочие дни: занятия на эти даты не планируются | MVP |
| FR-032 | Фиксация занятия: оно остаётся на месте при перегенерации | MVP |
| FR-033 | Осознанное нарушение правила: составитель может разместить занятие вопреки правилу, указав причину; система помечает такое занятие предупреждением | V2 |

## 12. Нефункциональные требования

| ID | Требование |
|----|-----------|
| NFR-01 | Автогенерация расписания университета укладывается в разумное время (минуты) и может быть остановлена |
| NFR-02 | Проверка конфликтов при правке занимает доли секунды |
| NFR-03 | Доступ по ролям, пароли хранятся в защищённом виде, соединение зашифровано |
| NFR-04 | Интерфейс работает в современных браузерах и удобен на телефоне |
| NFR-05 | Простой старт: пошаговая первоначальная настройка |

## 13. Вне рамок

- Оценки, домашние задания, учебные материалы (задачи LMS).
- Роли студента, родителя, руководителя.
- Выбор курсов студентами, индивидуальные расписания.
- Экзамены и бронирование аудиторий под мероприятия.
- Мягкие ограничения с весами, несколько вариантов расписания, сценарии «что если».
- Интеграции со SIS и LMS, SSO, открытый API.
- Несколько кампусов и факультетов в одной системе.

---

## 14. Состав первой версии (MVP)

1. Справочники и импорт из Excel.
2. Обычные правила (FR-020…026) и исключения (разовые изменения, праздники, фиксация).
3. Автогенерация, ручная правка, подсветка допустимых слотов, поиск свободной аудитории.
4. Конфликты с понятной причиной и предпросмотром последствий.
5. Черновик и публикация, история версий, журнал изменений.
6. Отсутствие преподавателя, список затронутых занятий, подсказка замены, уведомления.
7. Кабинет преподавателя: расписание, недоступные часы, отсутствие.
8. Просмотр, PDF и Excel, публичная ссылка, мобильная версия.
9. Отчёт по нагрузке преподавателей, роли, три языка, резервные копии.
